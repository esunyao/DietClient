# 记录这一餐

Android／Windows 在共享原生功能开关开启时使用真实采集页，沿用绿色卡片、紧凑表单与底部提交。读取采集策略和服务端草稿；策略或列表读取失败可分别重试。新建失败后的显式重试复用同一个 UUID 幂等键。可选择恢复、取消删除或确认删除草稿。

Android 使用系统相机／相册，Windows 使用文件选图；按真实文件内容与服务端策略校验 MIME、大小、数量，不裁剪餐盘。图片先进入待上传区，显式点击后按每张 presign → 独立无认证 PUT → confirm 串行执行，文件扩展名与 MIME 一致。可取消上传；部分失败保留本页图片与已完成阶段，重试跳过已确认图片。上传地址过期时，用户显式重试会释放旧图片占位并用原本地图片重新签名；已删除图片不占用数量。已确认图片使用短期预览地址，失效可刷新会话。

Android 丢失结果只通过共享媒体协调器恢复，核实账户、用途与采集会话 UUID；恢复后待用户确认上传。页面不自行消费系统丢失结果，不持久保存图片、健康数据或签名 URL。离开页面或换号取消上传，旧异步结果不可回写；服务端草稿可再次恢复。本地未上传图片与备注不会跨页面保存，切换草稿前提示清除。

餐别与备注按公开 API 提交；每次 submit／retry 都重新读取真实 AI 同意，读取失败、未授权、旧政策版本阻断，可进入「我的」授权页处理。202 仅表示异步受理，提交后进入餐食详情查看状态；失败会话可显式重新发起分析。成功变更集中失效草稿、会话、餐食、首页和趋势查询；冲突刷新服务端状态，保留安全本地输入供核对。

Web 与显式预览保留既有独立演示：示例选择不请求设备权限、不上传，演示提交仅写入共享内存状态，不生成真实营养结果。食堂菜单维持独立演示页。聚焦离线回归见 [采集测试](../../../../test/meal_capture_functional_test.dart)；真实设备权限、对象存储与服务联通仍需运行环境验收。
