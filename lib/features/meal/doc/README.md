# 餐食

历史与修正入口先选择真实或演示页面，真实模式不初始化演示表单、筛选控制器或样例状态。演示页面显式显示演示标记；演示修正使用共享未保存保护，返回和侧栏切换均需确认放弃修改。

Android/Windows 通过原页面中的平台开关接入真实接口；Web 保留下面的演示实现。真实历史把日期、餐别、关键词和页码交给服务端；详情展示分析状态、未知营养、404 与重试，删除需确认。失败分析重新核验 AI 同意后重试。可见且前台的待分析记录每 3 秒刷新，最多 2 分钟，离页或后台暂停，超时可手动刷新。

真实历史复用本机外观设置的紧凑列表／照片卡片：前者使用 96 方形缩略图与照片数量，后者使用横向封面与餐次元数据。照片进入相册，文字进入详情；原筛选、分页和未知营养语义保留。轮询包裹页面，每条记录直接交给页面 ListView，照片查询随视口挂载，避免整页同时请求。

真实修正保留时区、itemId 与原营养编码。仅改餐别、带时区时间或备注使用 PATCH 并始终带备注；菜品改动使用 PUT 提交完整餐次。每道菜至少一条非负营养值，重量可未知，已填值须在 0.001–100000 g 之间。修改重量不推算营养，未知不填零。失败保留草稿，未保存返回需确认，保存期间禁止重复提交；成功后重新读取服务器记录并使首页、历史、详情、趋势失效。独立手工新建暂未支持。

以绿色最终样板的历史、单餐详情和修正页为主要依据，使用共享 demo store 的餐食模型。历史支持日期、餐别、文本筛选、重置和逐批展示；手机餐食独立成行，宽屏按日期分组并提供选中记录预览。详情将整餐能量、宏量营养与未知指标集中展示，宽屏侧栏呈现营养及核对提示。手机详情与修正操作固定在底部，标题、滚动和安全区由 AppPage 处理。

修正表单通过 mealId 读取原餐；不传 mealId 时为手工新建，字段和营养初始为空，用餐日期采用共享演示日。编辑草稿在保存前不会改变统计，返回时对未保存输入进行确认。按餐别与时间、更新预览、实际份量组织主内容，宽屏将营养核对及备注放入侧栏；保存明确写入内存演示，关联页面读取同一状态，旧报告标记需更新。

提供设计说明指定的午餐煎鱼150g改120g样例。其他菜品或重量修改不推测营养，清空为未知并由用户核对整餐数值。未填写指标保留空值；不接入后端、真实识别或持久化。
