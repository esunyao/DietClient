# UI 迁移对照

主依据为新版需求 PPT v2261009、`20261002ui二次设计` 中 C/B 端最终 SVG、完整稿和设计说明；本轮校准同时对照用户提供的手机个人首页、平板机构首页两张目标图，量化目标见 [UI 规格](ui-spec.md)。React Native 源码只补充未绘辅助页。参考源只读，不将旧六导航和蓝色主题覆盖新设计。

| 功能 | 来源与范围 |
|---|---|
| home | 新版手机/平板首页；已知摄入、记录覆盖、下一步行动 |
| meal_record | 新版记录；示例图片、草稿、餐别与备注 |
| meal | 历史、详情、修正；手工补录为新建模式 |
| meal_plan | 三方案比较、替换与加入计划 |
| trend/report | 7/30/90日、逐营养素统计、报告版本与更新状态 |
| profile | 我的、健康档案、编辑与五类记录表单 |
| institution | 食堂菜单与餐食同步；计划/待确认/实际摄入分开 |
| auth/settings | 新版绿色外观；真实登录接入，注册/邮件仍为演示，设置保留模式选择 |

四主入口：首页、配餐、趋势、我的。详情与表单通过真实来源栈返回。本轮仅校准 UI，保持已有 Authentik/OIDC 登录、启动门控和共享内存交互，不扩展认证或网络能力；其他业务操作仍为明确的内存演示，不迁业务 API、相机、上传、持久化和 AI 服务。既有登录边界与历史验证状态见 [authentication](authentication.md)。

基础数据：早餐420与午餐680共1100kcal；加餐分析中。7日中6日有已知能量，9280÷6约1547。鱼份量修正样例使午餐620、当日1040、周期9220、日均1537。未知营养不补零，机构晚餐待确认不入账，旧报告保持原版本并标记需更新。

本表是页面来源与迁移范围，不是逐页视觉验收记录。集成阶段做约定的基础格式、静态分析、聚焦回归与必要的一次 Web 或 Windows 编译，实际结果在最终交付说明与 [README](../README.md) 记录。Android、功能、视觉与真机性能由用户验收，不把编译成功当作视觉一致性的证据。
