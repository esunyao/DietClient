# 页面功能迁移对照

主依据为新版需求 PPT v2261009、`20261002ui二次设计` 中 C/B 端最终 SVG、完整稿和设计说明；本轮校准同时对照用户提供的手机个人首页、平板机构首页两张目标图，量化目标见 [UI 规格](ui-spec.md)。React Native 源码只补充未绘辅助页。参考源只读，不将旧六导航和蓝色主题覆盖新设计。

| 功能 | 来源与范围 |
|---|---|
| home | Android/Windows 接入当天真实餐食与汇总；未设置营养目标保持未知 |
| meal_record | 真实策略、服务端草稿、图片直传、显式提交及失败重试 |
| meal | 真实历史分页、照片双视图、详情照片和全屏相册、元数据修改、整餐修正和删除；独立手工新建暂未支持 |
| meal_plan | 真实方案生成与计划保存无契约，显示暂未支持 |
| trend/report | 趋势接入7/30/90日真实汇总；报告生成与版本服务暂未支持 |
| profile | 我的、健康档案、编辑与五类记录表单 |
| institution | 菜单与餐食同步暂未支持；隐私遮罩可用，不展示虚构成员身份 |
| auth/settings | Android/Windows 注册、邮件重发、续期与可选记住登录；外观及历史紧凑列表/照片卡片偏好本机保存 |

四主入口：首页、配餐、趋势、我的。资料保留 self 身份、基础资料、头像、五类健康档案与 AI 同意；姓名只读。新功能仅装配 Android/Windows；Web 保留前序登录、资料和其余演示，显式 UI 预览不发送业务请求。真实失败和未知数据不回退样例，缺少接口不模拟服务器保存。协议和配置边界见 [authentication](authentication.md)。

Web 演示仍保留原样例及数据联动：早餐420与午餐680共1100kcal、加餐分析中。此类数值不填充真实模式。真实趋势以对应营养有值的记录日为均值分母，缺失值不补零；机构样例不入账。

本表是页面来源与迁移范围，不是逐页视觉验收记录。集成阶段做约定的基础格式、静态分析、聚焦回归与必要的一次 Web 或 Windows 编译，实际结果在最终交付说明与 [README](../README.md) 记录。Android、功能、视觉与真机性能由用户验收，不把编译成功当作视觉一致性的证据。
